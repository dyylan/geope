    geope.gecko¤

    geope.gecko.Gecko ¤

    Null-space optimiser for GEOPE solutions.

    Gecko post-processes an optimized Pulse solution: it moves the parameters within the Jacobian null space so that fidelity is preserved while an auxiliary cost is improved.

    Gecko is constructed from a Parameters object.

    g = Geope(p); g.optimize()
Gecko(g.params).smooth(...)

    The cost is an Objective from geope.objectives, or a weighted sum of them, passed to :meth:optimize::

    Gecko(g.params).optimize(Smoothness() + 0.1 * PulseLength())

    The single-objective methods (smooth, speed, bound, ...) are shorthands for one term.

    Because the functions are cached on params, Gecko reuses the Geope's already-compiled traces rather than recompiling.

    optimize(objective, *, piecewise_steps_multiplier=1, rate=0.01, max_steps=100, diff_tol=0.1, callbacks=None) ¤

    Minimise an objective, or a weighted sum of objectives, in the null space.

    Minimises the raw linear combination \(C(\phi) = \sum_i w_i c_i(\phi)\) by fixed-length steps along the null-space projection of \(-\nabla C\), so fidelity is preserved to first order. Only the ratios of the weights shape the trajectory; their overall scale changes what diff_tol means. Each term's unweighted value is reported every iteration in self.costs.

    geope.objectives¤

    geope.objectives ¤

    Composable null-space objectives for :class:geope.Gecko.

    An objective is a scalar cost of the projected pulse that Gecko lowers while moving only inside the Jacobian null space, so that fidelity is preserved to first order. Objectives are values, not procedures: each is a @dataclass(frozen=True) spec (value __eq__ and __repr__ for free, like the line searches) that knows how to turn itself into a cost function, and nothing about how that cost is minimised. The minimiser is Gecko's one projected-gradient step, which is what lets objectives be added together.

    Weighted sums. Objectives combine linearly with *, + and -::

    objective = 1.0 * Smoothness() + 0.1 * PeakAmplitude(parameter_labels=["XI"])
gecko.optimize(objective)

    which builds a :class:WeightedSum whose cost is the raw linear combination \(C(\phi) = \sum_i w_i c_i(\phi)\). Nested sums flatten, a scalar distributes over a sum, and the builtin sum works (sum([a, b])). Because Gecko takes a fixed-length step along the null-space projection of \(\nabla C\), only the ratios of the weights shape the trajectory; their overall scale changes only what diff_tol means. A zero weight is allowed and useful: the term is still evaluated and reported in gecko.costs but contributes no gradient (its input is wrapped in stop_gradient, so its backward pass is never traced). A negative weight is allowed too and maximises that term.

    The build contract. objective.build(params) -> cost resolves the spec against a :class:~geope.Parameters (labels to indices, bounds to arrays, the drift norm, the fidelity) and returns cost(phi), where phi is the real float64 projected pulse of shape (N_g, K_P) — K_P is the projected basis dimension, or n_experimental_params under param_transform — and the result is a real scalar. The cost must be traceable and differentiable almost everywhere. Gecko builds an objective after any subdivision, so a cost may close over the subdivided params.delta_t; every cost here is otherwise independent of piecewise_steps. Subclass :class:Objective (or wrap a function in :class:CustomObjective) to add a new one.

    Smoothness ¤

    Penalise jumps between consecutive segments, with zero endpoints.

    Cost: \(\|\phi_0\|^2 + \sum_g \|\phi_{g+1} - \phi_g\|^2 + \|\phi_{N_g-1}\|^2\) — the squared differences of the pulse padded with a zero segment at each end, so a pulse that switches on or off abruptly is penalised too.

    resolve_bounds(params, bounds) ¤

    Resolve a bounds map into per-column (K_P,) lower and upper bounds.
